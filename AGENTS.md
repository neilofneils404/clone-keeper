# Clone Keeper

An Omarchy plugin and bundled Python CLI for maintaining customized built-in
plugins with recorded ancestry, reviewed merges, recovery and undo.

## Development

- Treat /usr/share/omarchy and installed user plugins as read-only references.
  Use disposable source, plugin and state roots for tests and demonstrations.
- Runtime dependencies: Linux, Python 3.11+, Git. The native UI needs Omarchy's
  plugin-capable shell. Qt 6 qmllint provides optional candidate syntax checking.
- Run `python -m unittest discover -s tests -v`, `python scripts/demo.py`, and
  `scripts/check-ui.sh`. See docs/VALIDATION.md for native smoke checks.
- Keep CLI stdout machine-readable for --json; send diagnostics to stderr.
- Never infer historical ancestry from today's source. Baselines must be captured
  at creation, verified against an unchanged clone, or supplied explicitly.
- Preserve clone identity, binary files, modes and deletion conflicts.
- Status/review must not write live plugins or execute candidate code.
- Apply requires the reviewed candidate hash, rechecks inputs and retains backups.
  Advance the baseline to upstream, never to the locally customized result.
- Panel commands that change installed clones or call shell IPC must use --detach:
  Omarchy reloads Clone Keeper on those changes, which kills the panel's helper.
- Persist intent and snapshots before replacing a live directory. Use whole-tree
  atomic exchange, per-clone locks and recoverable journals. Refuse unknown edits.
- Do not commit generated bytecode, user snapshots, exports or machine settings.

## Release

Version 0.3.0 is a local beta. Keep validation claims evidence-based; do not equate
syntax checks or a clean merge with correct runtime behavior. See the release
checklist and submission draft in docs/RELEASE.md.
